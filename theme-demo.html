Buttons

Three weights, and the accent is the scarcest thing in the set: filled for the one primary action, a neutral border for ordinary ones, nothing at all until hover for repeated ones. Hover moves the border rather than the background, so an icon glyph can never merge into the fill behind it.

Inputs and selects

Inputs carry a visible border at all times, ramping default → hover → focus. The closed select is a ghost button; its open option list reverts to a normal readable surface.

Editorial

Long-form content inside the default surface.

An appearance name is a name that will eventually lie. The frame is a gray strip in light mode and a near-black one in dark, and it is the same token in both. 
:root {
  --surface-default:   light-dark(#ffffff, #16213a);
  --surface-secondary: light-dark(#f1f5f9, #060b14);

  /* Two on-colors, because a fill's text follows the fill's lightness. */
  --text-on-fill:  light-dark(#fff, #0b1220);  /* accent, success, danger */
  --text-on-light: #0f172a;                    /* warning */
}

.button:hover { border-color: var(--accent); }  /* never a background swap */

Contrast audit

Computed live from the resolved token values, recalculated whenever the scheme or an override changes. Thresholds are WCAG 2.1: 4.5 for body text, 3.0 for large text and non-text interface elements. Every pair passes in both schemes; if one ever fails here, it is a real finding in the palette, not a rendering artifact. Drive the overrides in the inspector to watch a passing palette break.

Lightness clamping

Applications that let users color items usually clamp lightness for legibility. The left column is the raw user color; the right is the same hue clamped to a light-mode ceiling of 78 and a dark-mode floor of 58, computed in CIELAB.
